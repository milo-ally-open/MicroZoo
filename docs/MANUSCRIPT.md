# MicroZoo — 物理 AI 模型研发与边缘平台部署流程

## 1. 整体流程

MicroZoo 采用五阶段研发体系：

| 阶段 | 名称                | 核心任务                                                     |
| ---- | ------------------- | ------------------------------------------------------------ |
| 01   | `01_model_train`    | 数据采集、数据集划分、数据预处理、模型设计、模型训练、精度评估、内存评估 |
| 02   | `02_model_convert`  | 模型导出、计算图转换                                         |
| 03   | `03_model_validate` | 数值一致性验证、任务精度验证、内存占用评估、运行时兼容性验证 |
| 04   | `04_model_optimize` | 目标硬件性能剖析、瓶颈分析、模型与算子优化                  |
| 05   | `05_model_demo`     | 最小可运行的端侧部署演示                                    |

重要原则：

- 第一阶段结束时，必须完成原始模型的任务精度评估和部署前内存评估。
- 第二阶段可以根据目标硬件平台的实际情况裁剪模型，但这不是必选步骤。
- 第三阶段必须验证转换后的模型是否保持原始模型的数值和任务精度，并验证目标硬件内存占用。
- 第四阶段必须在目标硬件上完成性能剖析，不能只依赖开发机数据。
- 第五阶段至少交付一个可运行的端侧部署演示程序。
- 每个阶段都必须形成可追溯的交付物。保证研发的可复现性。

# 01_model_train — 模型研发与训练

**目标：获得一个满足目标任务要求，并具备端侧部署可行性的原始模型。**

这一阶段不仅包括模型训练，也包括数据研发、模型设计、预训练模型适配以及模型容量评估等工作。不要求所有模型都从零训练，也不要求所有模型都必须使用预训练权重。要视具体情况分析，可能会有不同的方案。

## 1.1 任务定义与需求分析

任务定义和需求分析阶段首先明确模型要解决什么问题。

主要工作：

- 应用场景需求分析
- 模型任务定义
- 确定模型的输入与输出
- 确定要部署的硬件平台(可以是多个)

需要提前定义：

- 模型输入类型及输入尺寸。
- 模型输出结构。
- 目标任务精度。
- 预期推理延迟。
- 目标设备内存预算。

例如：

| 模型类别                   | 输入                       | 输出               |
| -------------------------- | -------------------------- | ------------------ |
| 目标检测                   | RGB 图像                   | 边界框与类别       |
| 分割                       | 图像 / 提示                | 分割掩码           |
| VLM（视觉语言模型）        | 图像 + 文本                | 文本 / 结构化输出  |
| VLA（视觉语言动作模型）    | 图像 + 指令 + 机器人状态   | 机器人动作         |
| 动作模型                   | 观测 / 状态                | 动作序列           |

- 公开数据集获取

- 标注与标签采集

对于具身智能模型，还需要采集：

- RGB / RGB-D 图像
- 机器人关节状态
- 末端执行器位姿
- 夹爪状态
- 动作轨迹
- 任务指令
- 任务回合元数据

**B. 数据集构建**

数据集构建：

- 数据清洗
- 数据标注
- 数据筛选
- 数据去重
- 数据质量检查
- 数据集整理

**C. 数据集划分**

数据集划分：

- 训练集
- 验证集
- 测试集

需要避免训练集与测试集之间的数据泄漏。

对于机器人时序数据，优先按照任务回合、轨迹、环境或采集批次划分，而不是简单地随机拆分相邻视频帧。

**D. 数据预处理**

数据预处理：

- 图像缩放
- 归一化
- 分词
- 数据编码
- 时间对齐
- 动作归一化
- 数据增强

最终形成可复现的数据预处理流程。

- Hugging Face 模型库

主要工作：

- 论文研读
- 架构分析
- 源代码分析

- 模块设计
- 输入 / 输出设计
- 损失函数设计

例如：

- 骨干网络设计

## 1.5 原始模型精度评估

**首先评估原始模型是否真正满足任务要求。**

使用独立的 测试集 进行最终任务精度评估。

| 模型类型       | 评价指标                        |
| -------------- | ------------------------------- |
| 目标检测       | mAP、精度、召回率            |
| 分割           | mIoU、Dice 系数                  |
| 分类           | 精度、F1 分数                |
| VLM            | 任务相关准确率          |
| VLA            | 动作误差、任务成功率 |

必须提前设定项目验收标准。

例如：

- 目标检测：mAP 达到项目要求。
- 分割：mIoU 达到项目要求。
- VLA：真实任务成功率达到预期。

不能只记录训练损失，还需要形成正式的原始模型精度报告。

## 1.6 部署前内存评估

**目标：在转换模型之前，判断原始模型是否具备部署到目标设备的内存可行性。**

这是第一阶段的重要检查节点。

分为两个等级。

### 等级 1 — 静态内存估算

先估算静态内存。

首先根据模型参数量和权重精度，估算理论权重占用。

公式：
$$
M_{\text{weights}}=\sum_i\frac{N_i b_i}{8}
$$
其中：

- $N_i$：对应权重张量的参数量。
- $b_i$：每个参数的位数。
- $M_{\text{weights}}$：理论权重内存。

常见精度：

| 精度 | 每个参数的位数 | 每个参数的内存占用 |
| --------- | ---------------- | ------------------ |
| FP32      | 32               | 4 字节            |
| FP16      | 16               | 2 字节            |
| BF16      | 16               | 2 字节            |
| INT8      | 8                | 1 字节             |
| INT4      | 4                | 0.5 字节           |

例如：

200M 参数模型，FP16：

$$
200\times10^6\times16/8=400MB
$$
注意：量化模型还需要考虑缩放因子、零点偏移、分组参数等额外开销。如有需要，还应进一步估算推理内存：

$$
M_{\text{inference}}=
M_{\text{weights}}+
M_{\text{activations}}+
M_{\text{workspace}}+
M_{\text{cache}}+
M_{\text{runtime}}+
M_{\text{输入 / 输出}}
$$
其中：

- 权重：模型权重。
- 激活值：中间激活。
- 工作空间：算子及推理引擎工作空间。
- 缓存：键值缓存（KV Cache）、特征缓存等。
- 运行时：框架和运行时开销。
- 输入 / 输出：输入输出张量。

不同模型需要重点关注不同部分：

- 视觉：特征图和中间激活值。
- 视觉语言模型（VLM）：视觉特征、语言模型权重及键值缓存（KV Cache）。
- VLA：视觉特征、状态输入、动作序列及多模块内存。
- 大语言模型（LLM）：权重、键值缓存（KV Cache）和上下文长度。

### 等级 2 — 开发机内存测试

开发机实际内存测试。

使用 RTX 4070 SUPER 等开发机运行完整模型，测量实际推理内存。

测试条件：

- 批大小
- 输入分辨率
- 序列长度
- 数据精度
- 摄像头数量
- 动作预测时域
- 模型执行路径

记录：

- 峰值已分配内存
- 峰值已预留内存
- 推理延迟
- 吞吐量

对于多模块模型，必须测量完整推理过程，而不是仅测单独的子模块。

注意：桌面 GPU 的显存峰值不能直接等同于 Jetson 的统一内存占用，等级 2 的测试主要用于开发阶段的容量筛选。

### 部署可行性判定

综合：

1. 静态权重内存占用。
2. 推理过程内存估算。
3. 开发机实际峰值内存。
4. 目标设备可用内存。
5. 目标任务的精度要求。

最终形成：

- 可行：具备初步部署可行性。
- 有条件可行：需要调整模型、精度或输入规模。
- 暂不可行：当前模型方案不适合目标设备。

如果不满足要求，返回模型研发阶段调整方案。

# 02_model_convert — 模型导出与转换

**目标：将原始模型转换为目标硬件推理框架可以执行的模型格式。**

## 2.1 模型导出

根据模型类型选择导出方式。

常见路线：

### 计算机视觉

```
PyTorch
   |
   v
ONNX
   |
   v
转换为目标运行时格式
```

### 自然语言处理 / LLM

```
Hugging Face Transformers
   |
   v
模型权重转换 / 计算图捕获
   |
   v
转换为目标运行时格式
```

### 具身智能 / VLA

```
PyTorch 模型组件
   |
   v
模块拆分
   |
   v
ONNX / 中间表示
   |
   v
转换为目标运行时格式
```

对于复杂 VLA，可以尝试拆分：

- 视觉编码器
- 语言编码器
- 多模态投影层
- 动作解码器

注意：ONNX 是常用的中间表示，并非所有模型都必须导出为 ONNX。具有动态控制流、特殊算子或复杂多模态结构的模型，需要根据目标运行时选择转换路径。

## 2.2 计算图转换

主要工作：

- 计算图优化
- 常量折叠
- 算子融合
- 形状变换
- 动态形状配置
- 不支持算子的替换
- 模块拆分

## 2.3 精度转换与量化

选择目标推理精度：

- FP32
- FP16
- BF16
- INT8
- INT4
- 混合精度

量化方式：

- PTQ：训练后量化。
- QAT：量化感知训练。

QAT 在第一阶段训练中实施；PTQ 通常在模型转换或优化阶段实施。

如果使用 PTQ，需要准备独立的校准数据集，并记录校准配置。

## 2.4 推理引擎构建

以 NVIDIA 为例：

```

  |
  v

  |
  v
```

主要工作：

- TensorRT 解析器
- 精度配置
- 优化配置
- 工作空间配置
- 插件集成
- 引擎构建

TensorRT 引擎应满足目标 Jetson 的硬件和软件环境要求。桌面 GPU 生成的引擎不应默认直接复制到 Jetson 使用。

# 03_model_validate — 模型验证

**目标：验证转换后的模型是否正确、精度是否满足要求、内存是否符合目标硬件约束。**

这是模型转换完成后的正式质量验证阶段。

特别注意：这里的精度验证不只是检查张量输出是否相似，还要检查实际任务精度。

## 3.1 数值一致性验证

数值一致性验证。

对比原始 PyTorch 模型和转换后的模型。

常见指标：

- MAE
- 最大绝对误差
- 相对误差
- 余弦相似度

检查：

- 输入 / 输出形状
- 张量数据类型
- 张量数值误差
- 预处理一致性
- 后处理一致性

例如：

```
PyTorch FP32
      |
      v
参考输出
      |
      | 对比
      v
TensorRT FP16
      |
      v
转换后输出
```

量化模型允许存在合理数值误差，必须根据任务要求确定容差，不能要求 INT8 与 FP32 逐位一致。

## 3.2 任务精度验证

任务精度验证。

使用同一套测试数据集，对比：

- 原始模型精度
- 转换后模型精度

例如：

| 指标      | 原始模型 | 转换后模型 | 差值 |
| --------- | -------- | --------- | ---------- |
| mAP       | 实测     | 实测      | 计算       |
| 精度 | 实测     | 实测      | 计算       |
| 召回率    | 实测     | 实测      | 计算       |

对于 VLA：

- 动作预测误差
- 任务成功率
- 轨迹质量

需要明确项目允许的精度退化范围。

**任务精度验证不等于数值一致性验证，两者必须分别报告。**

## 3.3 内存验证

目标硬件内存验证。

在实际目标设备上运行转换后的模型，测量：

- 模型权重内存
- 运行时内存
- 激活值内存
- 工作空间内存
- 峰值内存占用
- 可用内存余量

重点检查：

- 是否发生内存不足（OOM）。
- 是否能够完整执行推理。
- 动态输入是否引起额外内存分配。
- 多模块模型是否能够同时或按需加载。
- 是否满足目标设备的内存预算。

对于 Jetson Orin Nano Super 8GB，需要注意 CPU 和 GPU 共享统一内存，不能将 8GB 全部视为模型可用空间。

最终形成正式的内存验证报告。

## 3.4 算子与运行时兼容性

检查：

- 算子支持情况
- 不支持的算子
- 插件兼容性
- 动态形状兼容性
- 运行时加载
- 推理稳定性

### 阶段 03 交付物

```
03_model_validate/
│
├── numerical_validation/
├── accuracy_validation/
├── memory_validation/
├── operator_compatibility/
├── runtime_validation/
└── validation_report.md
```

**必须交付：**

1. 数值一致性报告
2. 任务精度验证报告
3. 内存验证报告
4. 算子兼容性报告
5. 运行时兼容性报告
6. 模型验证摘要

**阶段验收：数值误差在允许范围内、任务精度达标、内存满足目标设备要求，且运行时正常运行。**

如果失败：

- 数值或算子问题：返回第二阶段。
- 精度不达标：检查转换精度、校准和模型配置，必要时返回第一阶段。
- 内存不足：返回转换阶段调整模型，或进入有明确资源方案的优化迭代。

# 04_model_optimize — 模型优化

**目标：基于目标硬件的真实执行数据识别性能瓶颈，并针对模型、计算图、算子和运行时进行优化。**

核心原则：

**性能基线 → 性能剖析 → 瓶颈分析 → 优化 → 重新剖析**

## 4.1 目标硬件性能基线

在目标硬件上建立性能基线。

对于 NVIDIA Jetson：

- TensorRT
- CUDA
- Nsight Systems
- Nsight Compute
- trtexec
- tegrastats

记录：

- 推理延迟
- 吞吐量
- GPU 利用率
- CPU 利用率
- 内存占用
- 内存带宽
- 内核执行时间
- 功耗
- 温度

对于 VLA，还需要记录：

- 策略推理延迟
- 动作生成时间
- 端到端控制延迟

## 4.2 硬件性能剖析

必须在目标硬件上进行性能剖析。

通过实际运行数据判断：

- 哪些算子耗时最高？
- 哪些层存在计算瓶颈？
- 是否存在显存带宽瓶颈？
- 是否存在大量内核启动？
- 是否存在 CPU / GPU 同步开销？
- 是否存在内存分配和数据搬运开销？

## 4.3 瓶颈分析

根据性能剖析结果分类。

| 瓶颈类型              | 典型表现             |
| --------------------- | -------------------- |
| 计算受限         | 计算吞吐受限         |
| 内存带宽受限          | 内存带宽受限         |
| 内核启动开销受限          | 内核启动开销较大  |
| CPU 处理受限             | CPU 预处理或调度受限 |
| 数据传输受限        | 数据传输受限         |
| 同步等待受限 | 同步等待开销较大     |

## 4.4 针对性优化

根据瓶颈选择优化方式。

**模型级优化**

- 量化
- 模型剪枝
- 知识蒸馏
- 分辨率调整
- 架构修改

**计算图级优化**

- 计算图融合
- 层融合
- 算子替换
- 计算图简化

**内核级优化**

- CUDA C++
- Triton
- CUTLASS
- TensorRT 插件
- 自定义 CUDA 内核
- 内核融合

# 7. 项目验收清单

每个模型项目必须完成以下验收。

| 阶段              | 必须通过的检查                                               |
| ----------------- | ------------------------------------------------------------ |
| 01_model_train    | 数据集准备完成、原始模型可运行、任务精度达标、内存可行性评估通过 |
| 02_model_convert  | 模型导出成功、目标格式构建成功、转换配置完整                 |
| 03_model_validate | 数值一致性通过、任务精度通过、内存验证通过、运行时兼容     |
| 04_model_optimize | 完成目标硬件性能剖析、瓶颈分析、性能优化和精度回归验证     |
| 05_model_demo     | 完整应用可运行、系统测试通过、演示可复现、交付资料完整      |

**MicroZoo 的核心研发原则：**

1. 数据优先：模型研发必须建立在可靠的数据基础上。
2. 精度优先：首先确保原始模型达到任务精度要求。
3. 转换前先评估部署容量：必须确认目标设备能容纳模型及其推理开销。
4. 先验证，再优化：转换后先验证正确性和精度，再进行优化。
5. 先剖析再优化：在目标硬件上定位瓶颈，再实施优化。
6. 优化后重新验证：每次优化后都必须重新验证精度和性能。
7. 以演示应用为导向的交付：最终交付完整应用，而不是孤立的模型文件。
